Custom actions, ready to build

Hold Ctrl+Shift+Space or a mouse button, say what to do, and likh does it. Your phrases match instantly; ChatGPT picks only when none match.

One action, five stages

Triggerkey, mouse button or likh ctl
Hearraw transcript, no cleanup
Matchyour phrases, then ChatGPT
Run stepspaste, keys, open, wait, ask, run
Resultpaste, replace, pill, nothing

Three ways to start one

TriggerHow
Action keyCtrl+Shift+Space by default, changed on the Actions tab. Same hold, tap and silence-stop rules as dictation.
Mouse buttonMiddle, back or forward, picked on the Actions tab beside the key. Each button does one job, so back can dictate while forward runs actions. Same hook as today, installed only while a button is picked.
likh ctlaction-start, action-stop: for a Stream Deck, a script, or an agent testing.

An action is one small file

In LIKH_HOME/actions/, one TOML file each, with a schema and a README for agents. likh actions check and likh actions test "…" work without likh running.

# actions/make-this-formal.toml
name = "Make this formal"
description = "Rewrite the selected text in a given tone"
say = ["make this {style}", "rewrite this as {style}"]
input = ["selection"]
output = "replace"

[[do]]
ask = "Rewrite this in a {style} tone. Keep its meaning and language.\n\n{selection}"

Decided

Everything we settled, in one table (17 rows)
ScopeCustom actions only. Styles per app dropped.
TriggerIts own key (and now mouse button). Dictation's inline commands stay as they are.
MatchingExact phrases first, normalized. {text} only at the end; named lists in the file; alternates are more say entries. No match: ChatGPT picks from actions' names and descriptions; unsure means nothing runs.
Fallback scopeEvery action unless router = false; a run step it picked always asks first.
CleanupNone on action speech. Dictionary names fixed in slot text locally.
FilesOne TOML per action, reread on each press (no watcher), duplicate phrases are a load error.
Stepspaste, keys, open (URL-encoded slots), wait, ask (ChatGPT prompt), run (argv, no shell, context as env vars and JSON on stdin, stdout is the result, 30 s timeout, killed by PID).
InputDeclared per action: what you said, selection (Ctrl+C, clipboard restored), clipboard, app, window title.
Outputpaste, replace, notify, none. If the window in front changed, it goes to the clipboard instead.
TrustA script runs only after you approve it in the panel; a changed one needs approval again, with a diff. No likh ctl approve.
ConfirmIn the pill: the action key again to run, Esc or 5 s to cancel. Peach ring.
ConcurrencyOne action at a time; dictation still works.
HistoryLogged; paste and replace results count for paste last.
PillSpark glyph on the left; states as in the pill mockup. No-match shows what was heard.
PanelSeventh tab, Actions: action key and mouse button, list with a switch each, errors with file and line, Review and Approve, a form for simple actions.
Ships withREADME, schema, "make this {style}", "new thread {text}" (T3 draft link), a disabled run-tests example.
PlatformWindows. Not offered on macOS yet.

Defaults I filled in

  • No-match shows what was heard; the confirm ring is peach.
  • Review shows a diff; each action has a switch; the key lives on the Actions tab.
  • The fallback sees every action unless opted out.
  • check and test work offline; a focus change sends results to the clipboard.

How I'll prove it works

Test plan: 6 layers, each reported with real output in the PR
  1. Unit tests: matching (slots, lists, normalization, collisions), loading and check errors with line numbers, each step, trust hashes and diffs, router parsing, the mouse button's job mapping, pill and tab views through the iced simulator.
  2. End to end with fakes: each starter action from a TTS WAV through likh ctl action-start/stop, with LIKH_TRANSCRIBER=echo: and LIKH_PASTE=<file>, asserting exactly what was pasted, replaced or opened.
  3. Live, ignored by default: does the Codex endpoint accept a tool? If not, the router asks for JSON in plain text, and the PR says which shipped. One ask round trip.
  4. The running app through verify-likh: every pill state and tab view screenshotted against the mockups; approving a changed script by hand.
  5. Idle cost with measure-idle.ps1 before and after: zero frames and no polling while idle.
  6. cargo clippy -D warnings, cargo fmt, then bun run check once.

I won't switch a mouse button on in your running likh (AGENTS.md). Mouse triggering is covered by tests and a likh I start myself with its own LIKH_HOME, and only if you OK the hook while it runs.
